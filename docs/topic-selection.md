## 3. 페인포인트 → 해결 기능

| # | 페인포인트 | Base에서 확인한 근거 | 해결 기능 | 측정 지표 (Before → After) |
| --- | --- | --- | --- | --- |
| P1 | **증상에 맞는 런북을 못 찾는다** | "web-01 CPU 급증"에 DB Down 런북 제시 | 런북 **RAG** (질문 + 모니터링 알림으로 의미 검색) | 런북 매칭 정확도 |
| P2 | **표현이 조금만 달라도 엉뚱하게 응답한다** | "느려지고 CPU가 치솟았어요" → 잡담으로 분류 | LLM **라우팅** + 판단 이유 + 폴백 개선 | 라우팅 정확도, N회 반복 일치율 |
| P3 | **AI 답변을 믿어도 되는지 모르겠다** | 검증이 "30자 + `1)` 포함"만 확인 | **LLM-as-Judge** 4기준 + **근거 일치(Faithfulness)** 검사, 답변에 근거 출처 표시 | 근거 일치율, 평가 점수 |
| P4 | **기준 미달 답변인지 알 수 없다** | 3회 실패 시 "합격"으로 바꿔 그대로 전달 | 이중 카운터 + **품질 미달 안내** (Graceful Degradation) | 미달 응답 안내 비율 |
| P5 | **위험한 조치를 실수로 할까 두렵다** | 승인 단계 없음 | 재시작·롤백 포함 시 **Human-in-the-loop 승인** (`interrupt`) | 승인 없이 노출된 위험 조치 수 |
| P6 | **기다리는 시간이 길고, 일부가 실패하면 다 실패한다** | MCP 공용 Lock으로 직렬 실행, task 격리 없음 | **멀티에이전트 병렬 조사** + task 단위 에러 격리 + 부분 결과 표시 | 조사 소요 시간, 장애 주입 시 응답 성공률 |
| P7 | **대화가 끊기면 처음부터 다시 설명해야 한다** | 메시지만 저장, 그래프 상태 미저장 | LangGraph **체크포인터** + `thread_id` (HITL 재개에도 필요) | 재시작 후 대화·승인 대기 복원 |
| P8 | (팀 리드) **품질·비용을 볼 수 없다** | 평가·피드백 코드 없음 | LangSmith **Dataset 평가**, 👍/👎 **Feedback**, 비용 집계, 프롬프트 Hub | 실험 점수 비교, 요청당 비용 |

## 5. 주의할 점

- 런북·모니터링 데이터는 **직접 작성한 가상 데이터**다. 실제 회사 데이터가 아니라는 점을 README와 발표에 명시한다
- 임베딩 모델: 비용 없이 하려면 Ollama 임베딩 모델을 추가로 받아야 한다 (다운로드 시간 고려)
- 비용 단가는 실제 요금표가 아니면 "가정값"으로 표시한다
- 후보 B를 고르면 위 표의 영역은 대부분 그대로 쓰고, MCP 서버·데이터·프롬프트와 Before 버전을 새로 만들어야 한다
