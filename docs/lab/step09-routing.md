# Step 9 — 질문 이해와 범위 판정 (분기 재설계 1차)

## 목표
"EU REACH 란 무엇이고 가장 최근 변경은?"에 미국 TCE 관보로 답하거나(이전), 제품 20개 전체를 EU 목록으로 판정해 "변경 영향"으로 올리던(패치 후) 문제를 구조로 고친다.
질문을 **한 번 이해하고**, 실행 전에 **할 수 있는 것과 없는 것을 코드가 정하고**, 범위 밖·확인 불가는 **코드 문구로 답한다**. 다른 지역·다른 질문으로 대신 답하지 않는다.
함께: 대화 답변의 "담당자 승인"을 없앤다 (승인해도 실제로 일어나는 일이 없었다 — 설계 9절).

설계: [docs/routing-architecture.md](../routing-architecture.md)

```
질문 + 앞 턴 ─▶ understand (코드: 지역·제도·물질·제품·연도·범위 밖 표현 / LLM: 의도 분해 최대 3개)
              ─▶ inform    (범위 밖·확인 불가 안내 · 규제 설명 · 목록 조회 · 앞 답변 근거)
              ─▶ chat | lookup | briefing | (바로) finalize
              ─▶ finalize  (안내 → 설명·목록 절 → 본 답변)
```

## 만드는 파일

| 파일 | 역할 |
| --- | --- |
| `app/agents/understand.py` | 이해 노드: ① 코드 추출 ② 의도 분해(LLM → 형식 오류면 코드 규칙 → 코드 보정) ③ 후속 질문(앞 턴 대상·근거) ④ 범위 판정 → 경로 |
| `app/domain/coverage.py` (수정) | 제도 사전(다루는 11종 → 규제 ID, 다루지 않는 제도 13종), 범위 밖 표현(물성·법률·보안), 연도, 수집 가능 지역·기간 |
| `app/domain/responses.py` | 범위 밖·확인 불가 문구 (무엇을 · 왜 · 대신 할 수 있는 것) |

| `mcp_servers/reg_db_server.py` (수정) | `regulation_overview`: 카탈로그·등재 수·확인일·최근 등재일별 물질 |
| `app/llm/*` (수정) | 의도 분해 스키마·프롬프트, Fake 규칙(=형식 오류 시 대신 쓰는 코드 규칙) |

## 설계 포인트
- **코드가 우선**: 지역·제도·물질·제품은 코드가 뽑고, LLM은 "무엇을 원하나(의도)"만 나눈다. LLM 결과는 코드가 보정 (근거 없는 "설명" 제거, 제품·물질이 있으면 조회 추가)
- **요청한 의도와 실행한 의도를 나눈다**: "중국 최근 변경"은 의도 표시에는 `변경 브리핑`으로 보이고, 실행은 하지 않고 "확인할 수 없음"으로 답한다
- **목록 조회는 코드가 쓴다**: 등재 수·날짜·물질명은 LLM이 바꿀 여지가 없게
- **다른 질문으로 대신 답하지 않는다**: 다루지 않는 국가만 물으면 기본 지역(국내·미국)으로 채우지 않는다
- **후속 질문**: 대상이 없으면 앞 턴의 대상(제품·물질·지역)과 근거를 이어받는다

## 실제로 겪은 문제
- **패치가 증상을 옮김** — 지역 보정 후 "EU 변경" 질문이 "제품 20개 전체 목록 대조"로 바뀜 (`gate`의 수집기 없는 지역 분기) → 이해 단계에서 능력 판정, 분기 제거
- **"오늘 점심 메뉴 추천해줘"가 "대체 물질 추천"과 같은 범위 밖으로** — "추천해"를 화학 지식 신호로 씀 → 화학 문맥("대체 물질")만
- **"태국 규제 변경"이 국내·미국 브리핑으로** — 지역이 없으면 기본 지역을 쓰는 규칙 → 다루지 않는 국가만 물었으면 기본값을 쓰지 않음
- **"납이 RoHS 대상이야?"에서 납을 못 찾음** — "납품·납기"와 겹쳐 한글 "납"을 막아 둠 → 질문에서 조사와 함께 단독으로 쓰였을 때만 인정
- **설명 절에서 모델이 변경을 해석해 씀** — 변경은 코드가 쓰는 절의 몫이라고 지시
