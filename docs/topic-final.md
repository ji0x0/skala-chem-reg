# 최종 주제 — 공정 운전 이상 조사 에이전트

4단계 최종안. 1차 [topic-selection.md](topic-selection.md), 2차 [topic-domain.md](topic-domain.md)를 거쳐 결정했다.
품질 시험 이상(후보 D) 대신 **공정 운전 이상**으로 바꾼 이유는 아래 1장에 있다.

> 개인 경력·경험은 **1장(주제 선정 근거)에서만** 참고했다. 2장 이후의 공정 설계, 페르소나, 페인포인트는 경력과 무관하게 일반적인 화학 공정 운전 상황을 기준으로 정의한다.
>
> 이 서비스는 **조사와 권고만** 한다. 공정 제어값을 쓰거나 설비를 조작하지 않으며, 데이터는 전부 직접 만든 가상 데이터다.

## 1. 왜 공정 운전 이상인가

| 기준 | 후보 D (품질 시험 이상) | **공정 운전 이상** |
| --- | --- | --- |
| 이전 LangChain 실습과 겹침 | 같은 QC 시험 데이터, 판정 로직 재사용 → 겹쳐 보일 위험 | **실험실 시험값이 아니라 공정 센서 시계열** → 겹침 적음. "계산은 코드, 해석은 LLM" 원칙만 이어감 |
| Base 구조 대응 | 1:1 | **더 자연스러움**: Base의 "시스템 모니터링 → 런북"이 "공정 태그 모니터링 → 운전 절차서"와 거의 같은 형태 |
| 전공·경력 연결 | QC, 화장품 | **재료화학공학(반응·열전달)**, 공정안전 경진대회(PS 공정 P&ID, 과압 해소, 폭주반응 예방), **산업안전기사**, 폴리부텐 **컴파운딩** 연구, 6시그마(관리도) |
| HITL 설득력 | 재시험·불합격 승인 | **운전 조건 변경·정지 승인** — "AI는 권고, 조작은 사람"이라는 이유가 훨씬 분명 |
| 가드 게이트 소재 | 수치 교정 | 수치 교정 + **금지 조치 차단**(인터록 해제, 안전밸브 차단 등은 코드로 막음) |
| 어려움 | 데이터 작성 | 시계열 데이터를 생성해야 함 |

**판단: 좋은 선택이다.** 이전 실습과의 중복 걱정이 해소되고, Base 구조와 더 잘 맞고, 안전(승인·금지 조치) 측면에서 멀티에이전트·HITL·가드 게이트를 쓸 이유가 분명해진다.
대신 두 가지는 지켜야 한다.
- 시나리오는 **일반적인 공정 인과관계**(냉각 부족 → 온도 상승 등)로 단순하게 만든다
- LLM에게 원시 시계열을 넘기지 않는다. **코드가 추세·변화율·임계 초과를 요약**하고 LLM은 그 요약을 해석한다

## 2. 대상 공정 (가상)

일반적인 고분자 생산 라인을 단순화한 3개 단위 (중합 → 컴파운딩 → 원료 이송).

| 단위 | 태그 예 | 대표 이상 시나리오 |
| --- | --- | --- |
| **R-101 중합 반응기** (발열, 재킷 냉각) | 반응 온도 `TI-101`, 압력 `PI-101`, 냉각수 유량 `FI-102`, 교반기 전류 `II-103` | 냉각수 유량 저하 → 온도 상승 (폭주 전조) |
| **EX-201 이축 압출기** (컴파운딩) | 배럴 존 온도 `TI-201~204`, 용융 압력 `PI-205`, 토크 `II-206`, 스크류 rpm `SI-207` | 스크린 막힘 → 다이 압력 상승 / 히터 밴드 고장 → 존 온도 하락·토크 상승 |
| **T-301 원료 탱크 / P-301 이송 펌프** | 레벨 `LI-301`, 토출 압력 `PI-302`, 진동 `VI-303` | 펌프 캐비테이션 → 진동 증가·토출압 변동 |
| (함정 시나리오) | 위 태그 중 하나 | **센서 드리프트**: 계측기만 이상, 실제 공정은 정상 → 교정 이력으로 구분해야 함 |

## 3. 페르소나

### 주 페르소나 — 입사 1년 차 공정 엔지니어 (교대 지원)

| 항목 | 내용 |
| --- | --- |
| 상황 | 야간에 "R-101 반응 온도 상승" 알람. 반장은 원인과 조치를 묻는데 어디부터 봐야 할지 모름 |
| 목표 | 15분 안에 원인 후보를 좁히고, 절차서 기준 조치와 승인이 필요한 조치를 구분해 보고 |
| 현재 방식 | 히스토리안 추세 화면, 알람 이력, 정비 이력, 운전 절차서(PDF)를 각각 열어 확인 |
| 쓰는 화면 | 사용자 프론트엔드 (채팅 + 조사 진행 상황 + 승인 요청) |

### 보조 페르소나 — 생산팀장 (운전 책임자) / 공정안전 담당

| 항목 | 내용 |
| --- | --- |
| 목표 | 이상 조사가 절차대로 근거를 갖춰 이뤄지고, 운전 조건 변경은 반드시 승인을 거치게 하기 |
| 걱정 | AI가 수치를 지어내거나, 인터록 해제 같은 금지 조치를 권하는 것 |
| 쓰는 화면 | 승인 요청 + 관리자 대시보드 (LangSmith: 조사 트레이스, 평가, 피드백, 비용) |

## 4. 페인포인트 → 해결 기능

| # | 페인포인트 | 해결 기능 | 측정 지표 (Before → After) | 요구사항 |
| --- | --- | --- | --- | --- |
| P1 | **알람은 결과일 뿐, 원인 태그를 찾기 어렵다** | 연관 태그 추세를 코드로 요약(변화율, 임계 초과 시점, 선후 관계) → LLM 해석 | 원인 후보 정확도 | R18, R21 |
| P2 | **히스토리안·정비 이력·절차서를 오가야 한다** | MCP 서버 3개 + 조사 서브에이전트 **병렬 조회** | 조사 소요 시간 | R04~R08, R13, R30 |
| P3 | **센서 고장인지 공정 이상인지 헷갈린다** | 계측기 교정·정비 이력 교차 확인, 동일 현상의 다른 태그와 비교 | 센서 드리프트 오판율 | R19 |
| P4 | **해당 상황의 절차서·과거 사례를 찾기 어렵다** | 운전 절차서·비상 대응·과거 사례 **RAG** | 절차서 매칭 정확도 | R19, PDF 1 |
| P5 | **조치 판단이 부담스럽고 위험하다** | 운전 조건 변경·정지 권고는 **HITL 승인**, 금지 조치는 **가드 게이트로 차단** | 승인 없이 노출된 조치 수, 금지 조치 노출 수 | R18, R33, PDF 4 |
| P6 | **교대 인수인계 때 조사 맥락이 끊긴다** | `thread_id` 체크포인터로 조사 상태·승인 대기 복원 | 재시작 후 복원 여부 | R33, R34 |
| P7 | **보고서 근거가 부족하다** | LLM-as-Judge 4기준 + 근거 일치, 확인 못 한 항목 명시 | 근거 일치율, 평가 점수 | R20~R23, R27 |
| P8 | (팀장) **조사 품질·비용을 볼 수 없다** | LangSmith Dataset 평가, Feedback, 비용 집계, Prompt Hub | 실험 점수, 요청당 비용 | R39~R44 |

## 5. 서비스 구성

```
Vue 채팅 화면 ──(REST + SSE, CORS)──▶ FastAPI
                                      │  lifespan: LLM · MCP 클라이언트 · 체크포인터 · 그래프 1회 생성
                                      ▼
                         LangGraph Supervisor (LangChain 모델·프롬프트·구조화 출력)
   route → plan → gate → [공정 데이터 | 정비·계측 | 절차서 RAG] 서브에이전트 병렬
         → 충분성 확인(재조사, 상한) → 분석 → 작성 → 검증 → (조치 포함 시) 승인 → 확정
                                      │
         MCP: historian(태그 시계열·추세 Tool) / maintenance(알람·정비·교정 Tool)
              / ops-docs(절차서·사례 Resource, 조사 절차 Prompt) / 외부 MCP 서버 1개
                                      │
                 SQLite(체크포인터·운전 데이터) · 벡터 저장소 · LangSmith(관리자 대시보드)
```

## 6. 진행계획 (Google Spread 등록용)

**주제**: 공정 운전 이상 조사 에이전트 — Base 장애 대응 에이전트 구조를 화학 공정 운전 도메인으로 전환하고, 멀티에이전트·RAG·HITL·가드로 개선 (2번 신규 프로젝트, Base 구조 재사용)

| 순번 | 영역 | 무엇을 만드나 / 바꾸나 | 추가 설명 | 우선 |
| --- | --- | --- | --- | --- |
| 1 | 데이터 | 가상 공정 데이터 구축 | 3개 단위 태그 시계열(시나리오별 생성 스크립트), 알람·정비·교정 이력, 운전 절차서·비상 대응·과거 사례 문서, 정답 라벨 평가 질문 세트 | M |
| 2 | MCP | MCP 서버 3개 + 외부 서버 1개 | `historian` / `maintenance` / `ops-docs` 직접 제작, 외부 MCP 서버(예: SQLite) 연결, 멀티 서버 클라이언트 | M |
| 3 | 가드 게이트 | 수치는 코드, 해석은 LLM + 금지 조치 차단 | 변화율·임계 초과·선후 관계는 코드가 계산. 인터록 해제·안전장치 우회 같은 조치는 코드로 제거 | M |
| 4 | RAG | 절차서·사례 의미 검색 | Before: Base 방식 키워드 규칙 / After: 벡터 검색. 매칭 정확도 비교 | M |
| 5 | 멀티에이전트 | Supervisor + 조사 서브에이전트 병렬 | 공정 데이터 / 정비·계측 / 문서 서브에이전트(LangGraph ReAct). 에러 격리, 부분 결과 표시 | M |
| 6 | 품질 검증 | LLM-as-Judge + 근거 일치 | 원인 후보·근거·조치·확인 못 한 항목 필수. 재작성 상한, 미달 안내 | M |
| 7 | HITL | 조치 승인 노드 | 운전 조건 변경·정지 권고 시 `interrupt()`로 승인 요청, 승인 후 확정 | M |
| 8 | 라우팅 | 질문 유형 분류 | 단순 조회(태그 현재값, 절차서 문의) / 이상 조사. 판단 이유 포함 | M |
| 9 | 세션 | LangGraph SQLite 체크포인터 | 교대 인수인계: 재시작 후 조사·승인 대기 복원 | M |

## 7. 주의할 점

- **안전 고지**: 실제 공정 제어·안전 판단에 쓰는 도구가 아니며, 권고는 운전 책임자 승인이 전제라고 화면·README·발표에 명시
- 데이터·태그명·절차서는 전부 가상이다. 실제 기업의 공정·제품 정보는 쓰지 않는다
- 시계열 생성 스크립트는 시나리오별 정답(원인, 기대 조치)을 함께 만들어 평가 세트로 재사용한다
- 처음엔 시나리오 6~8개(정상 1, 이상 5~6, 센서 드리프트 1)로 시작한다
